# AGENTS.md — правила работы с сайтом-портфолио

Файл для агентов и для себя. Описывает, как устроен сайт, что можно менять
автоматически, а что только руками.

## 1. Что это за проект

Статический сайт без сборщика, фреймворков и зависимостей: чистые HTML, CSS, JS.
Хостинг — GitHub Pages, репозиторий `fedoroj/fedoroj.github.io`, ветка `main`,
публикуется из корня. Адрес: **https://fedoroj.github.io/**

Ключевое разделение, которое нельзя нарушать:

| Слой | Файлы | Кто меняет |
| --- | --- | --- |
| Код | `css/*.css`, `js/*.js` | агент, только по явной задаче |
| Контент | `site.md`, `cases/*/*.md`, `assets/**` | агент (кейсы) и владелец (остальное) |

Контент **никогда** не встраивается в код. Он читается в рантайме по путям,
которые указаны в `site.md`. Поэтому добавление кейса не требует правок JS/CSS.

## 2. Структура

```
index.html              оболочка страницы, подключает css и js
404.html                страховочная страница для несуществующих адресов
site.md                 контент главной: тексты, пути к медиа, список кейсов
cases/<slug>/
  <slug>-case.md        статья кейса
  assets/               ассеты кейса (относительные пути в md)
css/                    reset, variables, base, layout, main
js/                     content-state, main, cases, theme, page-enter, ui-sounds
assets/                 fonts, images, video, logos, preview, vendor
build_index.py          версии css/js/шрифтов + Open Graph из site.md
subset_fonts.py         пересборка подмножеств шрифтов
scripts/check_site.py   проверки перед публикацией (запускаются в CI)
.github/workflows/      CI: проверки на каждый пуш
```

## 3. site.md — простая CMS

`site.md` — единственное место, где меняются тексты главной и пути к файлам.
Это обычный Markdown с таблицами. Каждая строка таблицы — поле.

- **Тексты задаются парой RU | EN.** Пустой English означает «взять русский».
- **Тексты и типографика правятся только в `site.md` и `cases/*.md`**, не в коде.
- В текстах стоят **неразрывные пробелы** (U+00A0) перед длинным тире и после
  коротких предлогов, неразрывный дефис в `QR‑код`, среднее тире в диапазонах.
  Это не случайные символы: при правках сохраняйте их, иначе поедут переносы.
- **На десктопе (≥1025px) у страницы увеличенные боковые отступы**:
  `16 + --side-controls-width (75px) + 16 = 107px`. Это место под фиксированное
  боковое меню слева и переключатели языка/темы справа. Меняете ширину меню —
  меняйте `--side-controls-width` в `variables.css`. Ниже 1025px шапка
  плавающая, там обычные 16px.
- **Пути к медиа** — локальные (`assets/images/...`) или полные HTTPS.
- Пути с компьютера (`/Users/...`) при публикации не работают.

Основные разделы: `Главный заголовок`, `Аватарка`, `Описание`, `Статус`,
`Кнопки`, `Работы` (+ блоки `### Кейс: ...`), `Архив`, `Галерея`, `Артефакты`,
`Обо мне`, `Публикации`, `Контакты`, `Подвал`, `Настройки вкладки`.

### 3.1. Аватарка и постер

| Параметр | Значение |
| --- | --- |
| Превью | `assets/images/greeting-serge-gif.gif` |
| Постер | `assets/images/greeting-serge-poster.jpg` |
| Тип превью | `auto` |

`Постер` — необязательный статичный кадр (первый кадр анимации). Он показывается
мгновенно, а GIF подменяет его после загрузки. Это сделано потому, что аватарка
весит ~850 КБ и без постера задерживает первый экран.

- Форматы постера: **только `.jpg` / `.jpeg` / `.png`**.
- Постер должен быть **первым кадром** GIF, иначе при подмене будет заметный
  скачок. Если первый кадр с фоном — `.jpg`, если прозрачный — `.png`.
- Поле пустое или превью — видео → постер не используется.

## 4. Как добавить или обновить кейс

Кейсы — зона агентов. Владелец вручную правит только аватарку, видео о себе,
CV, контакты и тексты главной.

### Шаг 1. Папка кейса

```
cases/<slug>/
  <slug>-case.md
  assets/cover.jpg
  assets/demo.mp4
  ...
```

`<slug>` — латиница, цифры, дефисы, без пробелов. Внутри `md` пути
**относительные**: `assets/cover.jpg`, `assets/demo.mp4`.

### Шаг 2. Статья

Обычный Markdown. **Первым идёт изображение обложки, только потом `# Название`** —
кейс открывается с картинки. Дальше `##` разделы.
Изображения — `![alt](assets/cover.jpg "Подпись")` (подпись становится `figcaption`),
видео — `![](assets/demo.mp4)` (станет `<video controls>`, автоплея нет).

**Первое медиа статьи должно совпадать с полем `Медиа` карточки в `site.md`**:
модалка открывается тем же кадром или видео, что и карточка, и **без подписи**.
Ссылайтесь на общий файл относительным путём от папки кейса, например
`![](../../assets/images/cases/case_21_9.jpg)`. Если поменяли медиа карточки —
поправьте первую строку статьи.

Статьи архива (`### Архив:` в `site.md`) — исключение: там **только медиа**
с подписями, заголовок и короткий подзаголовок одной строкой. Никаких абзацев
текста: архив открывается как галерея. Языковые блоки `## Русский` / `## English`
в архивных файлах обязательны — по ним статья делится на языки.

### Шаг 3. Блок в site.md

Добавляется внутрь раздела `## Работы`, порядок блоков = порядок карточек:

```markdown
### Кейс: <slug>

| Поле | Русский | English |
| --- | --- | --- |
| Название | Название кейса | Case name |
| Год | 2025-2026 | 2025-2026 |
| Описание | Одна-две фразы о проекте и роли | One or two sentences |
| Теги | Финтех; B2B; App | Fintech; B2B; App |

| Параметр | Значение |
| --- | --- |
| Цвета тегов | lime; cyan; violet |
| Медиа | assets/video/video_case_2-35-1.mp4 |
| Тип | auto |
| Медиа для мобильных | |
| Тип для мобильных | auto |
| Ширина | full |
| Подпись | Подпись обложки | Cover caption |
| URL RU | cases/<slug>/<slug>-case.md |
| URL EN | |

| Русский | English | URL RU | URL EN |
| --- | --- | --- | --- |
| Читать кейс | Read case | cases/<slug>/<slug>-case.md | |

| Медиа | Тип | Ширина | Подпись RU | Подпись EN |
| --- | --- | --- | --- | --- |
| cases/<slug>/assets/process.jpg | auto | | Подпись кадра | Frame caption |
```

Обязательные таблицы: поля карточки, параметры, ссылки (минимум одна строка).
Таблица «Галерея» необязательна: это дополнительные кадры сторителлинга.
Пустые ячейки допустимы.

Карточка — мини-сторителлинг: название, год, описание, теги и ссылки сверху,
под ними обложка (`Медиа`) и кадры «Галереи» друг за другом, без бенто-сетки.
Клик по обложке или кадру открывает просмотрщик и листается только внутри
этого кейса; название и ссылки по-прежнему открывают статью в модалке.
В карточке до 6 медиа вместе с обложкой (проверяет `check_site.py`); в статье
кейса ограничений нет. Подписи необязательны и выводятся по центру.
Пустая `Ширина` кадра берёт ширину обложки.

Пути в таблицах карточки считаются от корня сайта (`cases/<slug>/assets/...`),
в самой статье — от папки статьи (`assets/...`).

- `Цвета тегов`: `red, orange, amber, yellow, lime, green, teal, cyan, blue,
  indigo, violet, purple, pink, brown, gray`. Несколько — через `;`.
- `Тип`: `auto` (видео по `.mp4`/`.webm`, остальное — картинка), либо явно
  `image`, `gif`, `video`. Нужен для URL без расширения.
- `Ширина`: `full`, `min` или число в пикселях.
- `URL EN`: если пусто, английская версия показывает русский файл.

### Шаг 4. Проверка

- размеры медиа — по лимитам из раздела 6;
- открыть сайт локально (двойной клик по `Запустить сайт.command`);
- убедиться, что карточка и статья открываются, картинки на месте.

Код при этом **не меняется**. Сборку запускать не нужно.

### 4.1. Окно кейса и его закрытие

На телефоне кейс открывается как bottom sheet: панель выезжает снизу вверх,
а при закрытии **уезжает вниз** (`case-sheet-out` в `main.css`). Анимацию
запускает `closeCaseDialog()` в `js/cases.js`: ставит класс `is-closing`,
ждёт `animationend` и только потом вызывает `dialog.close()`.

Поэтому **вызывать `dialog.close()` напрямую нельзя** — окно захлопнется без
анимации. Все точки закрытия (кнопка «Закрыть», клик вне окна, Escape, свайп
вниз) идут через `closeCaseDialog()`. На планшете и десктопе окно закрывается
мгновенно, выезда там нет.

Размер наборного текста в статьях — токен `--article-font-size` (`14px`),
он же действует на таблицы внутри кейса.

## 5. marked.min.js — как работает

`assets/vendor/marked.min.js` — вендорная библиотека **marked v12.0.2**
(MIT), парсер Markdown в браузере. Это **не контент**, а библиотека.

- Подключена обычным `<script>` в `index.html` и создаёт **глобальный `marked`**.
- `js/cases.js` использует `marked.lexer`, `marked.parse`, `marked.parseInline`
  и собственный `marked.Renderer`.
- Порядок скриптов важен: marked подключается **до** `js/cases.js`.
- Не переименовывать, не переносить, не бандлить и не оборачивать в модуль:
  файл уже минифицирован, выгода от объединения нулевая, а глобальный
  `marked` сломается.
- Обновление версии = замена файла; после этого запустить `python3 build_index.py`.

### Санитизация

После парсинга HTML фильтруется (`markdownFragment` в `js/cases.js`):

- разрешены только: `P BR HR STRONG EM DEL A IMG H1-H6 UL OL LI BLOCKQUOTE
  PRE CODE TABLE THEAD TBODY TR TH TD FIGURE FIGCAPTION VIDEO SOURCE`;
- все атрибуты снимаются, кроме обработанных вручную: `href`, `src`, `alt`,
  `title`, `poster`, `start`;
- `style`, `class`, `id`, `onclick` и прочие атрибуты, `<script>`, `<iframe>`,
  `<svg>` вырезаются, неизвестные теги удаляются вместе с содержимым.

Отсюда правило: в статьях **нельзя** рассчитывать на inline-стили, классы,
`<div>`-вёрстку и встраиваемые виджеты. Только обычный Markdown.

## 6. Медиа: форматы и лимиты

Разрешены: **jpeg, png, gif, mp4, webm**. Формат **WebP не используется** —
решение владельца, не предлагать и не добавлять.

| Тип | Лимит | Комментарий |
| --- | --- | --- |
| JPG | ширина ≤ 1400 px, 150–250 КБ | основной формат фото и обложек |
| PNG | только если нужна прозрачность | иначе переводить в JPG |
| GIF | ≤ 500 КБ | короткие циклы; GIF плохо сжимается |
| MP4 | 720p, ≤ 10 МБ, `+faststart` | основной формат видео |
| WebM | ≤ 10 МБ | альтернатива MP4 |

- **Автопроигрывание видео зависит от звуковой дорожки.** Без дорожки ролик
  играет сам, с дорожкой — только по действию пользователя. Список готовит
  `build_index.py` через `ffprobe` в `assets/video/audio-manifest.json`;
  громкость не оценивается, важен сам факт наличия дорожки. После добавления
  или замены видео запустите сборку, иначе новый файл попадёт в «со звуком».
- Имена файлов — латиница, цифры, дефисы. Без пробелов и кириллицы.
- Замена файла **с тем же именем** — рабочий способ обновить медиа.
  Кэш GitHub Pages — 10 минут, столько может показываться старая версия.
- Одинаковые файлы лучше не дублировать по папкам, но если кейс самодостаточен —
  дубликат допустим.
- Тяжёлое видео и GIF проверять после заливки: `du -sh` и вес конкретного файла.

## 7. Темы (светлая и тёмная)

Сайт имеет две темы: `body[data-theme="light"]` и `body[data-theme="dark"]`,
переключение — `js/theme.js`, выбор запоминается.

- Любые новые медиа проверять **в обеих темах**: прозрачные PNG/GIF должны
  читаться на светлом и на тёмном фоне.
- Не вшивать белый или чёрный фон в прозрачные ассеты.
- Скриншоты интерфейсов, светлые макеты — на тёмной теме они выглядят
  как светлые прямоугольники, это нормально, но рамку/фон не добавлять.

## 8. Мультиязычность (RU / EN)

- Язык хранится в `<html lang>`, переключатель меняет тексты на лету.
- В `site.md` каждый текст — пара `Русский | English`. Пустой EN = русский.
- В разметке `index.html` пары хранятся в `data-ru` / `data-en`.
- Статья кейса: отдельные `.md` на каждый язык, пути в `URL RU` / `URL EN`.
  Пустой `URL EN` → английская версия открывает русский файл.
- При добавлении кейса без английского перевода оставляйте `URL EN` пустым,
  но **не** оставляйте пустыми English-ячейки у `Название` и `Описание` —
  лучше продублировать русский текст, чем показать пустую карточку.

## 9. Производительность: что уже сделано и что нельзя ломать

Эти решения приняты осознанно, не откатывать:

- **Шрифты урезаны** до символов из контента (`pyftsubset`, все вариативные оси
  сохранены). Если добавили текст с новыми символами (другая письменность,
  редкие знаки) — запустить `python3 subset_fonts.py`, иначе символы
  подставятся из системного шрифта. Требуется `pip3 install fonttools brotli`.
  Оригиналы шрифтов — вне репозитория, путь передаётся аргументом.
- **У шрифтов есть версия в URL** (`?v=hash`), её расставляет `build_index.py`
  и в CSS (`url("../assets/fonts/...")`), и в `<link rel="preload">`. Это
  критично: iOS Safari упорно кэширует шрифты по адресу и после замены файла
  может продолжать отдавать старую (или битую) копию — текст уходит на
  системный шрифт, и выглядит это как «шрифт не загрузился». Не убирать
  версии из CSS вручную: они пересчитываются при каждой сборке.
- **`site.md` кэшируется** на проде (`cache: 'default'`) и всегда свежий
  локально. Не возвращать `cache: 'no-store'` для продакшена.
- **Логотип в подвале** — `loading="lazy"`, не убирать: он весит ~260 КБ.
- **Иконки переключателя темы встроены в CSS как data URI.** Это не прихоть:
  иконки нарисованы через `mask`, а если файл маски не загрузился, браузер
  рисует вместо иконки пустоту — на тёмном фоне кнопка «пропадает». Файлы
  `assets/icons/sun-20.svg` и `moon-20.svg` остаются источником: поменяли
  иконку — перекодируйте её в data URI в правилах `.icon--sun` / `.icon--moon`
  (`css/main.css`).
- **Аватарка** — постер + подмена на анимацию после загрузки.
- **Статьи подогреваются** при наведении на ссылку кейса (`prefetchCase`).
- **Изображения из Markdown** получают `loading="lazy"` автоматически.

## 10. Сборка и публикация

```bash
# только если меняли css/js, Title или Site URL:
python3 build_index.py

# проверка локально:
# двойной клик по «Запустить сайт.command»

git add -A
git commit -m "что изменено"
git push
```

GitHub Pages пересобирает сайт за 30–60 секунд.

**Когда сборка НЕ нужна:** добавление кейса, замена картинок/видео,
правки текстов в `site.md` и `cases/*.md`.

### 10.1. Проверка перед пушем

`python3 scripts/check_site.py` — битые ссылки, пути к медиа, один `h1`,
валидный JSON-LD, отсутствие `text-rendering: optimizeLegibility` в CSS
(он ломал шрифты в Safari) и ссылок на WebP. Тот же скрипт плюс проверка
актуальности версий ресурсов запускается в CI на каждый пуш:
`.github/workflows/check.yml`. Если проверка упала — публиковать нельзя.

### 10.2. Страница 404

`404.html` — статическая страница для несуществующих адресов. Цифра набрана
той же типографикой, что крупные контакты (селектор `.link--display,
.not-found__code` в `main.css`), поэтому меняется вместе с токенами контактов.
`build_index.py` проставляет в неё те же версии css/js, что и в `index.html` —
не забывайте про неё при переименовании стилей. Стоит `noindex, follow`:
сама страница в поиск не попадает, но ссылки с неё обходятся.

## 11. Чего не делать

- Не менять вручную `?v=` у css/js в `index.html` — это делает `build_index.py`.
- Не переименовывать и не переносить `css/`, `js/`, `assets/`, `cases/`.
- Не добавлять сборщики, фреймворки, npm-зависимости, CDN-скрипты.
- Не добавлять WebP.
- Не встраивать контент в JS/HTML: тексты живут в `site.md` и `cases/`.
- Не удалять `.nojekyll` — иначе Pages включит Jekyll.
- Не коммитить `.DS_Store`, архивы и исходники видео.

| Задача | Кто |
| --- | --- |
| Новый кейс: папка, статья, ассеты, блок в `site.md` | агент |
| Замена медиа внутри кейса | агент |
| Аватарка, видео о себе, фото, CV | владелец вручную |

## 13. Тема и язык: как определяется (не «исправлять»)

**Тема** (`js/theme.js`) — от **местного времени посетителя**, а не от системной
настройки:

- 07:00–20:59 — светлая, 21:00–06:59 — тёмная;
- ручной выбор запоминается в `sessionStorage` и держится до закрытия вкладки;
- пересчёт при перезагрузке, на живой странице тема не переключается сама.

Скрипт стоит в начале `<body>`, чтобы не мигало. Если менять логику —
`resolveTheme(hour, savedTheme)` единственная точка принятия решения.

**Язык** (`js/main.js`) — `localStorage` → первый поддерживаемый язык браузера
(`navigator.languages`) → русский. Автоопределение не сохраняется, чтобы при
следующем визите снова учитывать настройки браузера. Переключение меняет
`<html lang>`, заголовок вкладки и мета-описания.

## 14. SEO и ATS: что лежит в index.html

- `<title>`, `meta description`, `canonical`, `robots`, `theme-color` — статично
  в разметке, потому что краулеры читают её до выполнения скриптов.
- `js/main.js` (`metaDescriptions`) поддерживает `description`, `og:description`,
  `twitter:description`, `og:locale` в согласии с языком интерфейса.
  При правке описания меняйте **и статичный `<meta>`, и этот объект**.
- JSON-LD (`Person` + `WebSite`) — структурированные данные для Google/Яндекса.
  Правьте `sameAs` и `knowsAbout` при смене ссылок и специализации.
- `<noscript>` — статическая версия: имя, роль, список кейсов, контакты.
  Основной контент грузится из `site.md`, поэтому без JS страница иначе пустая.
- `robots.txt` + `sitemap.xml` в корне. `site.md` и `cases/*.md` **нельзя**
  закрывать в robots: поисковик должен их прочитать, чтобы отрисовать контент.
- `lastmod` в `sitemap.xml` **не правится руками**: `build_index.py` берёт дату
  последнего коммита, менявшего `site.md` или `cases/`. Поэтому при правках
  контента запускайте сборку — иначе CI покажет расхождение.
- **Один `h1` на страницу**: имя в hero (`#heroName`). Описание — это `<p>`,
  не заголовок. `h1` внутри `<noscript>` виден только без JS.
- Комментарий в начале `index.html` — инструкция для ATS и ИИ-агентов.
  Держите его в согласии с фактами: если меняется должность, город, стек или
  статус поиска работы — обновите и комментарий, и JSON-LD.
- При смене домена обновить: `canonical`, `og:url` (генерируется из `Site URL`
  в `site.md`), JSON-LD `url`/`@id`, `sitemap.xml`, `robots.txt`.

## 15. Звуки интерфейса (js/ui-sounds.js)

Звуки — это готовый набор процедурных пресетов из скилла **sound**
(https://github.com/mishanaer/sound), без аудиофайлов и зависимостей.

**Модуль `js/ui-sounds.js` копируется из скилла без изменений.** Не переводить
комментарии, не оборачивать, не рефакторить, не добавлять настройки, громкость,
кнопку mute, новые пресеты и предзагрузку. Обновление — заменить файл целиком
и обновить хеш в `main.js` (см. ниже).

Пресеты: `press`, `click`, `tap`, `hover`, `select`, `toggle`, `tick`.
Один звук на одно взаимодействие.

Где подключено:

- `main.js` — делегированный обработчик ссылок: обычные ссылки и `mailto:`
  дают `click`, CTA и `[data-fancybox]` (картинки, артефакты) — `tap`.
  Карточки кейсов `[data-open-case]` здесь пропускаются: у них свой звук.
- `cases.js` — кнопки, переключатели, карточки кейсов, закрытие окна.
  Обработчики ставят `event.uiSoundHandled = true`, поэтому вложенный элемент
  не дублирует звук родителя.
- Пустое место, текст и фон **не озвучиваются**. Глобального «тапа по любому
  клику» быть не должно.

`prefers-reduced-motion` модуль соблюдает сам: при включённом «Уменьшении
движения» звук выключается. Это требование скилла — не обходить.

**Хеш версии в `js/main.js`** (`import('./ui-sounds.js?v=...')`) обновляется
вручную: `build_index.py` версионирует только `href`/`src` в `index.html`.
После замены файла: `shasum -a 256 js/ui-sounds.js | cut -c1-12`.

Если на iPhone тишина — сначала проверить переключатель «Бесшумный» на корпусе
и «Уменьшение движения» в настройках: iOS глушит Web Audio по обоим.
